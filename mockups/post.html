Building resilient web applications with modern CSS.

Cascade Layers, custom properties, and modern layout patterns can transform how we maintain interfaces at scale — if we let go of the pixel-grid mindset and design with the cascade.

By Jane Doe 15 March 2026 7 min

Modern CSS is no longer the cause of frontend complexity — it is the cure. For two decades the discipline accreted preprocessors, methodology dialects and component-scoped runtime stylesheets, all to compensate for one missing primitive: control over the cascade. That primitive arrived in 2022, and most teams still have not noticed.1

The thesis of this essay is small and unfashionable. Cascade Layers, custom properties and the new layout primitives are sufficient to retire most of the architectural scaffolding the frontend has built around CSS. What remains is editorial: deciding which decisions are global, which are sectional, and which belong to the page in front of you.

The problem with traditional CSS.

Every team that grows past a single product runs into the same two failures. First, specificity drift: utility classes lose to component classes lose to one-off overrides, and nobody can predict which selector wins without grepping the codebase. Second, token sprawl: design decisions multiply at every level of the stack until the system has six grays for the same shade and no one can throw any of them away.

A design system fails not when it has too few tokens, but when it loses the right to delete one. — from “Hairlines & the Politics of One Pixel.”

Enter Cascade Layers.

Layers solve specificity drift the way z-index ought to have solved stacking — by making the order explicit and naming it. We put resets, primitives, components and overrides into named layers, and the browser resolves them in the order we declare. The implication for design systems is that specificity becomes editorial: you choose the layer the rule belongs to, not the selector that wins.

@layer reset, tokens, primitives, components, overrides;

@layer tokens {
  :root {
    --paper: oklch(0.985 0.005 80);
    --ink:   oklch(0.22 0.018 60);
  }
}

@layer components {
  .post-title {
    font-family: var(--font-display);
    font-size: clamp(2.5rem, 6vw, 5.5rem);
    line-height: 0.98;
  }
}

This is the smallest interesting CSS you can write today. There is no preprocessor, no methodology, no scoped runtime — only the cascade, declared explicitly. The sample compiles unchanged in every browser shipped after late 2022.

The 3-tier design token system.

A token system fails when its tiers cannot defend their own boundary. We name three: primitives (the raw values, e.g. oklch(0.985 0.005 80)), semantic (the meaning, e.g. --paper), and component (the local override, e.g. --card-bg). The discipline is not that the tiers exist — it is that no rule may reach across them.

A worked example.

Consider a card that needs a background slightly darker than the page in light mode and slightly lighter than the page in dark mode. The naïve fix is a component token that flips with data-theme. The correct fix is a semantic token, --surface-elevated, defined once at the root and inherited everywhere a surface needs to lift.

:root {
  --surface-elevated: oklch(0.965 0.008 80);
}
[data-theme="dark"] {
  --surface-elevated: oklch(0.21 0.024 270);
}
.card { background: var(--surface-elevated); }

The card no longer knows what theme it is in. It only knows it is elevated. The system does the rest.

A closing observation.

The temptation, when modern CSS arrives, is to keep the architecture and use the new primitives as faster pavers. The harder, more interesting move is to remove the architecture and let the language do its job. The cascade is editorial. Use it that way.
